# Testing Profile – Common

本文件定义组织级测试规范的**不可变公共部分**。  
所有语言与框架的测试实践 **必须遵循本文件**。

---

## 一、测试的根本目标（不可争议）

测试的首要目标是：
1. 防止回归
2. 固化行为契约
3. 支撑安全重构

测试不是：
- 为了覆盖率数字
- 为了“让 CI 通过”
- 为了替代代码审查

---

## 二、测试组织结构（强约束）

所有项目的测试结构必须遵循以下语义分层：

```

tests/
├── unit/          # 单元测试（函数 / 类）
├── integration/   # 集成测试（模块协作）
├── contract/      # 契约测试（API / 配置 / 协议）
├── benchmark/     # 性能测试（可选）

```

### 语义约束

- unit 不允许依赖 IO / 网络 / 外部系统
- integration 允许真实组件协作，但必须可重复
- contract 用于保护公共接口与数据结构
- benchmark 默认不进入 CI 主流程

---

## 三、不可违反条款（Testing Constitution）

以下行为在任何项目中**禁止**：

1. 提交无任何验证方式的新逻辑
2. 测试依赖执行顺序或隐式状态
3. 测试直接修改真实生产资源
4. 使用 sleep 掩盖异步 / 并发问题
5. 为通过测试而弱化断言有效性

---

## 四、测试基本质量标准

每个测试必须满足：

- 独立、可重复
- 失败信息可读
- 不依赖外部状态
- 一次只验证一个行为

---

## 五、测试检查清单（通用）

- 是否存在已有类似测试可复用？
- 是否可以写成 unit 而不是 integration？
- 是否覆盖了错误与边界路径？
- 是否能清晰解释“失败意味着什么”？

---

## 六、与其他模块的关系

- Simple Development Mode：作为质量门禁
- Complex Development Mode：作为强制执行规范
- Architecture-heavy Extension：补充测试关注点
- Language Profile：提供具体实现方式
