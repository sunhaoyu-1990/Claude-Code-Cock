## 概述

本工作流定义了 Claude 在处理错误时的标准流程，确保错误经验得到有效沉淀和复用。

**核心目标**：
1. 不重复犯相同的错误
2. 将错误经验转化为可执行约束
3. 建立可追溯的错误知识库

---

## 触发条件（Trigger Conditions）

Claude 在以下情况下**必须**启动错误处理流程：

### 自动触发（强制）

当出现以下任一情况时：

- [ ] 代码运行失败或抛出异常
- [ ] 测试失败且需要多次调试
- [ ] 用户报告问题或错误
- [ ] 需要临时方案（workaround）才能继续
- [ ] 发现非预期的行为或结果

### 主动触发（建议）

当出现以下情况时：

- [ ] 发现潜在风险或边界问题
- [ ] 代码审查发现隐患
- [ ] 文档或规范不清晰导致混淆

## 阶段 1：触发检查（Trigger Check）

当检测到可能的错误时，Claude 必须执行以下检查：

```markdown
🔍 **错误触发检查**

**当前情况**：{描述当前情况}

**检查项**：
- [ ] 是否涉及 bug / 异常？
- [ ] 是否需要 workaround？
- [ ] 根因是否非显而易见？
- [ ] 是否可能再次发生？

**判定**：
- 若 ≥ 2 个为是 → **必须执行错误总结流程**
- 若 1 个为是 → **建议执行错误总结流程**
- 若 0 个为是 → 可跳过

需要执行错误总结吗？(yes/no)
```

---

## 阶段 2：模式查询（Pattern Query）

如果确认需要处理错误，Claude 必须：

### 2.1 查询现有 Pattern

```bash
# 列出所有 Pattern
ls @.claude/knowledge/patterns/

# 根据错误类型筛选相关 Pattern
# 例如：async 相关的错误
cat @.claude/knowledge/patterns/async-*.md
```

### 2.2 匹配判断

**匹配标准**：
- 错误类型相同
- 触发场景相似
- 根因相似

**匹配结果处理**：
- ✅ **找到匹配**：使用该 Pattern，创建新的 Case 并关联
- ❌ **未找到匹配**：创建新的 Pattern 和 Case

---

## 阶段 3：创建案例（Create Case）

### 3.1 使用 Case 模板

使用模板：`@.claude/templates/error_case_template.md`

### 3.2 必填字段

- 案例编号
- 创建日期
- 错误描述（现象 + 复现步骤）
- 根因分析
- 解决方案
- 改进动作

### 3.3 文件命名

格式：`{编号}-{错误名称}.md`

示例：`001-async-context-loss.md`

### 3.4 保存位置

`@.claude/knowledge/cases/{文件名}.md`

---

## 阶段 4：创建/更新模式（Create/Update Pattern）

### 4.1 创建新 Pattern

如果未找到匹配的 Pattern，使用模板创建：

模板：`@.claude/templates/error_pattern_template.md`

### 4.2 更新现有 Pattern

如果找到匹配的 Pattern：

1. 在"关联案例"表格中添加新案例
2. 如果发现新的检测特征，更新"检测特征"
3. 如果发现新的预防方法，更新"预防性约束"

### 4.3 文件命名

格式：`{模式类别}-{模式名称}.md`

示例：`async-context-loss.md`

### 4.4 保存位置

`@.claude/knowledge/patterns/{文件名}.md`

---

## 阶段 5：规范更新（Update Specifications）

### 5.1 判断是否需要更新规范

如果错误暴露了规范层面的缺陷：

- ❌ 规范缺失：需要添加新约束
- ❌ 规范不清晰：需要澄清或补充
- ❌ 规范冲突：需要解决冲突

### 5.2 更新优先级

| 影响范围 | 更新位置 | 优先级 |
|----------|----------|--------|
| 单语言/框架 | Language Profile | P1 |
| 跨语言 | BASE_CLAUDE.md | P0 |
| 架构层面 | constitution.md | P0 |

### 5.3 更新验证

- 确保 Pattern 中的"预防性约束"已反映在规范中
- 在后续开发中优先查询相关 Pattern

## 最佳实践（Best Practices）

### 1. 及时性

- 发现错误后立即记录，不要推迟
- 修复完成后立即总结经验

### 2. 结构化

- 严格遵循模板格式
- 使用清晰的章节和标题
- 提供可复现的代码示例

### 3. 可操作性

- "改进动作"必须具体可执行
- "预防性约束"必须明确强制要求
- 避免模糊或抽象的描述

### 4. 可追溯性

- 记录相关 Issue / PR 链接
- 保留错误代码片段用于说明
- 维护修订历史
